# Yeaft Showcase 讲稿

## 一句话定位

**Yeaft 是一个跨设备、可配置 AI 团队、面向任务执行的 AI 工作平台：你可以从手机发起复杂任务，让 AI 在连接的机器上工作，并通过 Work Center 把目标推进到可验收的结果。**

英文主标题：**Your AI team. Real work. From anywhere.**

记忆点：**手机是入口，AI 团队是执行者，任务完成才是目标。**

## 逐页讲述（建议 6–8 分钟，不含现场 Demo）

### 1. 不只是把 AI 聊天搬到手机

“如果我不在电脑旁，能不能仍然让 AI 帮我推进一个复杂任务？Yeaft 的答案不是在手机里再放一个聊天窗口，而是让手机连接真正的执行环境：我的项目、工具，以及一支可以自己定义的 AI 团队。”

### 2. 我想交出去的是任务，不是下一句提示词

“比如：修复这个 bug，补上回归测试，准备一个经过审查的 patch。它天然涉及调查、实现和审查，也很可能超过一轮对话。用户不应该始终坐在电脑前，在每一步之间搬运上下文、安排角色、反复说继续。”

该例为建议场景，不能暗示已经在这份演示里完整执行成功。不说所有其他产品都做不到。

### 3. 手机负责指挥，Agent 负责执行

“Yeaft 把交互设备和工作机器分开。手机、平板和桌面浏览器经过 Server 连接所选 Agent。文件操作、Shell 和模型调用都在 Agent 一侧。手机不需要装完整开发环境，就能给已有的执行环境下达任务。”

一句补充：需要网络可达、Server 可访问、Agent 在线；不是离线手机执行。

### 4. 离开电脑，不必离开任务

“我可以在手机上打开 Session，给出目标、查看各个角色的回复、补充约束。回到桌面浏览器，仍然访问同一个 Agent 的 Session。设备变化了，任务上下文不必从头解释。”

展示移动端截图。它是实际 UI 的移动 viewport，数据为 staged 只读检查，不是已验证的公网跨设备任务案例。

### 5. AI 团队，而不只是单个助手

“一个 Session 可以从一个 VP 开始，再按任务加入更多 VP。实现者负责产出，审查者负责质疑，研究者负责补齐依据。不同职责放在同一可见的对话里，但贡献保留各自身份。”

不要说多个模型天然独立或结论一定更准确。Linus / Martin 是示例团队，不是强制产品流程。

### 6. 不只是选头像，而是定义怎么工作

“我可以通过 VP persona prompt 定义角色职责，通过 Project instruction 和仓库文档定义共享标准。比如只做最小改动、审查精确版本、部署前询问、没有运行过的测试不能说通过。这些不是每次聊天都要重复提醒的话，而是可以复用的工作规则。”

这是主差异点之一。可控 System Prompt 不等于绕过运行时安全边界，也不是沙箱。

### 7. 从和 AI 一起做，到把任务交给 AI

“Session 适合探索、讨论和实时协作；目标明确后，Work Center 让用户交出目标、约束和验收条件，而不必写好每一步提示词。AI 规划和执行工作，记录结果，需要人判断时再把具体问题交回来。”

保留 Preview。它不是另一种聊天模式，不暗示 Session 自动迁移。Work Center 按任务的执行者配置选择 VP，不表示 Session 成员自动全部继承。

### 8. 不是只得到一句‘已完成’

“AI 的执行连接到真实文件和终端。用户可以查看源文件，也能查看命令和结果。证据不是这款产品的全部，但它让任务自动化变得可以检查。”

图中为 `node --check` 的实际采集回放，只有语法检查范围。不要把 30 秒工具展示扩成整场语法检查教学。

### 9. 浏览器窗口关了，不代表目标消失

“Work Center 把目标持久化为 WorkItem，用 Action 和 Run 记录工作和尝试。用户关心的是目标、进度和结果，不用靠翻聊天记录猜它现在做到哪一步。执行在在线 Agent 侧，不依赖浏览器一直开着。”

Agent 下线不会继续计算；恢复必须遵循中断和外部副作用的安全边界。不要演示无依据的后台成功状态。

### 10. 自动化执行，人保留关键决定

“我希望减少的是逐轮监督，而不是放弃控制。明确范围内的工作自动推进；缺输入、遇到阻塞或不能安全继续时，明确要求决策。完成依据是验收，而不是模型结束了一轮回复。”

可称“有边界的任务自动化”。不说永不需要人、无权限限制、任意自动上线。

### 11. 竞争力在于组合

“单独看，移动访问、多个角色、可配置指令、任务自动化都可以被当作一个功能。但 Yeaft 把它们放在同一个工作体验里：我能从任意可联网设备指挥自己定义的 AI 团队，在连接的机器上推进真实目标。”

不用竞品 Logo 矩阵，不宣称独家，没有基准就不写提效倍数。

### 12. 从一个真实、边界清晰的目标开始

“连接一台有项目和工具的机器，定义你的 AI 团队，从手机发起一个小而完整的目标。先让一件真实工作走过请求、执行、检查和验收，再逐步扩大授权范围。”

落到仓库 README。主标题的收束：**Your next task does not have to wait for your desk.**

## 建议现场 Demo：一条主线，不要逐项点菜单

建议任务：**“修复一个预先复现的小 bug，添加回归测试，准备待审查 patch；不部署。”**

1. 用手机浏览器进入事先连通的 Agent / Session，展示明确目标与约束。
2. 展示实现者和审查者的 persona / 项目规则，解释不同职责，不现场长篇编辑 prompt。
3. 在 Work Center 明确创建目标与验收条件。不要假装普通 Session 会自动变成 WorkItem。
4. 展示 AI 执行进度，选择一个文件变更和测试结果作为代表证据。
5. 展示审查结论和验收状态；若遇 blocker，明确展示它为什么停下、需要什么输入。

演示前在隔离仓库预跑并记录实际命令、revision、结果。现场耗时长可使用**清楚标注的预录片段**，不能把 staged fixture 当成真实端到端执行录像。目前 PPT 内截图只承担真实组件展示，不证明这条建议任务已完成。
